## 1. 目标与边界

把论文写成可连续阅读、可按章节回查的中文版本。它是“结构化详译”，不是逐词直译，也不是第二份 Research Memo。

- 忠实保留作者的论证顺序、核心 claim、方法细节、实验设置、数值结论和限制。
- 允许合并同一段内重复修辞，但不得省略会改变技术含义的限定条件。
- 不把 project page、GitHub 或个人推断冒充论文原文。需要补充时使用明确标签：`项目页补充`、`代码页补充`、`译者注`、`我的判断`。
- Research Memo 负责评价；详译层默认不评价。若必须指出歧义，使用 `译者注：`，保持短而可验证。

## 2. 默认覆盖范围

对 `paper2zotero / 精读入库 / 写入 Zotero`，默认覆盖：

1. Abstract；
2. Introduction；
3. Related Work 的研究定位与关键差异，不机械罗列全部引用；
4. Method 全部核心小节；
5. Experiments：设置、baseline、metrics、主结果、ablation、failure；
6. Discussion / Limitations / Conclusion；
7. 对理解、复现或判断 claim 重要的 Appendix。

如果论文极长，正文仍须完整覆盖主论证；附录按“复现相关、评估协议、数据构建、额外结果、失败案例”的优先级详译。被压缩的附录必须列出省略范围，不能静默跳过。

### 原主流程的实施要求

对于“paper2zotero / 精读入库 / 写入 Zotero”或用户明确要求中文翻译的任务，在 Research Memo 后追加中文结构化详译。

像 Masked Visual Actions 示例那样，详译应做到：

- 从摘要、引言、方法、实验推进到讨论和关键附录；
- 在相应位置保留“图 X / 表 X / Appendix X”锚点及中文解释；
- 保留训练数据量、模型底座、LoRA、硬件、步数、指标、成功率、action space、评估协议等可复现信息；
- 对前向模型、逆向模型、规划、策略评估、动作提取等概念给出连贯中文说明；
- 对抽取时丢失的公式、变量、数值或相关系数回看 PDF，绝不输出残缺占位句；
- 明确区分作者 claim、项目页补充和个人判断。

不要把详译写成无换行的大段 PDF 抽取文本，也不要把 Research Memo 原样重复一遍。

## 3. 结构模板

保持原文编号与层级；英文标题可在首次出现时放在括号内。

```markdown
# 中文结构化详译

> 说明：本节按论文原文结构进行忠实中文转述；Research Memo 中的研究判断不混入本节。

## 摘要

## 1. 引言

## 2. 相关工作

## 3. 方法

### 3.1 ...

## 4. 实验

### 4.1 实验设置
### 4.2 主要结果
### 4.3 消融实验

## 5. 讨论、局限与结论

## 附录：关键补充材料
```

章节不存在时不要硬造。论文将 Discussion、Limitations、Conclusion 分开时，沿用原结构。

## 4. 忠实度规则

- 术语首次出现使用 `中文（English term）`；后续选择一种稳定写法。
- 模型名、数据集名、benchmark、缩写、变量名保持原文。
- 对论文中出现的前向模型、逆向模型、规划、策略评估、动作提取等概念给出连贯中文说明，不把它们压缩成孤立术语。
- 数字必须保留单位、样本数、训练步数、硬件、频率、维度、成功率和比较方向。
- 不把 correlation 写成 causation，不把 qualitative observation 写成定量结论，不把作者的 future work 写成已完成能力。
- `only / without / zero-shot / unseen / same weights / no task-specific fine-tuning` 等限制词必须翻出。
- 原文含糊时忠实保留不确定性，例如“作者未报告”“论文没有明确说明”，不得推测补全。
- 抽取文本损坏公式、变量或表格时，回看 PDF 原页；仍无法恢复则标记 `[原文符号未可靠提取]`。
- 不补写原文不存在的实验结论。项目页或代码补充必须独立标注来源。

## 5. 图表、公式与附录

### 图

在对应章节附近写：

```markdown
> 图 X（Paper Fig. X）：中文解释……
```

保留图号、图意、作者希望它支持的 claim。图已在 Research Memo 嵌入时，详译层可以引用同一图，不必重复上传；但仍要翻译 caption 的关键信息。

### 表

保留表号、metric 方向、数据集/任务、关键数值和对比结论。大表允许只重排关键列，但必须说明“仅摘录关键列”，不能把摘录伪装成完整表。

### 公式

核心公式保持原式，并紧接中文解释每个关键变量与该式在方法中的作用。不要只贴公式，也不要仅写模糊意译。

### 附录

优先保留：

- 数据构建与划分；
- 训练超参数和资源；
- evaluation protocol / prompt / scoring；
- controller、camera、calibration、action space；
- baseline 适配；
- 完整 failure 定义；
- 复现所需细节。

## 6. 压缩规则

可压缩：

- Related Work 中逐篇重复的文献罗列；
- 与正文重复的 appendix 叙述；
- 法务模板式 impact statement；
- 不影响理解的常规实现措辞。

不可压缩掉：

- 方法成立所需的假设；
- 数据量与数据来源；
- baseline 是否使用相同底座、数据或额外监督；
- 评价指标和评估者；
- 关键超参数与输入输出维度；
- 失败判定规则；
- 负结果、偏差、限制和未完成的开源承诺。

## 7. PDF 排版

- Research Memo 与详译在同一个独立 PDF 中使用两个一级标题，顺序固定为：`中文 Research Memo` → `中文结构化详译`。
- 详译较长时，按原文章节使用二级/三级标题，不为了压缩页数而删除原主流程要求的细节。
- 图随文走；不建立孤立的“图片仓库”小节。
- 同一视觉材料只嵌入一次，其他位置用文字交叉引用，避免 PDF 膨胀。
- Source anchors 使用 `Paper §3.2`、`Paper Fig. 4`、`Paper Table 2`、`Appendix E` 等人类可读格式。

## 8. 完成前核对

- 原文主章节是否全部有对应中文段落？
- Abstract、Method、Experiments、Limitations 是否都有覆盖？
- 数字、单位、模型名、数据集名、表号、图号是否与原文一致？
- 是否保留了否定词、条件词和能力边界？
- 作者 claim、项目页补充、译者注和个人判断是否清楚分开？
- 关键公式和损坏符号是否回看 PDF 原页？
- 重要附录是否覆盖；若压缩，是否明确列出范围？
- 详译是否连贯可读，而不是把 PDF 抽取文本机械拼接？
